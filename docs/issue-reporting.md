# Reporting RoadForge problems

Use the [RoadForge issue chooser](https://github.com/alteixeira20/RoadForge/issues/new/choose)
to select the report that matches the outcome you need:

- **Bug report** for reproducible behavior that differs from the intended result.
- **UX/usability problem** for a confusing, difficult, or error-prone workflow.
- **Feature request** for a focused user problem that current behavior does not solve.
- **Documentation problem** for missing, inaccurate, or unclear guidance.
- **Self-hosting/deployment problem** for installation, upgrade, backup/restore,
  rollback, or runtime failures.
- **Accessibility problem** for barriers involving keyboard use, assistive
  technology, semantics, reflow, contrast, motion, or touch.

Blank public issues are disabled so each report receives the minimum useful
context. Titles carry a consistent category prefix and forms apply a matching
triage label.

## Protect private data

Never publish credentials, passwords, tokens, secrets, invite links, session
data, roadmap exports, private roadmap content, database contents, private URLs,
or private logs. Share only the minimum non-sensitive reproduction context. Do
not attach a roadmap export to an issue.

Security vulnerabilities do not belong in any public form. Follow
[SECURITY.md](../SECURITY.md) and use GitHub private vulnerability reporting.
The chooser routes security reports to that private channel.
